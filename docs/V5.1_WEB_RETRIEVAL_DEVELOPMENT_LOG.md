## 1. 设计方案

V5.1 在现有 General Document Agent Core 上增加受控公开 Web 信息获取能力，不替换本地
`retrieve_document`，不修改 V4 Agentic Retrieval。整体分为六个独立边界：

```text
User task
  -> Source Router: LOCAL / WEB / BOTH / DIRECT_URL（只提供策略提示）
  -> Agent Tool selection
  -> retrieve_web
       ├── query -> replaceable SearchProvider -> normalized untrusted results
       └── URL   -> public URL policy -> pinned transport -> HTML parser -> WebDocument
  -> existing Safety + Tool Trace + untrusted Tool-result envelope
```

Source Router 不执行检索、不扩大 scope，也不调用或复制 V4 Agentic Retrieval。Agent 仍可在
本地请求中选择原有 Tool；系统 Prompt 明确要求只有公开网页、最新信息或用户显式 URL 才使用
`retrieve_web`。

Search Provider 使用 Protocol port，默认 `UnavailableSearchProvider` 明确返回未配置错误，不绑定
特定搜索网站、不伪造结果。部署方可以替换 provider adapter，而不改变 Tool、Agent 或安全层。

Direct URL 使用独立的 URL policy 和 transport：先规范化 URL、解析并验证全部 IP，再把 transport
固定连接到已验证公网 IP，同时保留 HTTP Host 和 TLS SNI。每次 redirect 都重新解析和验证，从而
避免只做字符串校验或 DNS rebinding。

## 4. WebDocument 与不可信数据契约

`WebDocument` 由 Python parser 生成，包含：

- `document_id`
- `url`
- `title`
- `content`
- `canonical_url`
- `domain`
- `publisher`
- `published_at`
- `metadata`

字段只来自 HTTP/HTML 的显式内容；缺失 title/publisher/published_at 时保持 `None`，禁止模型猜测。

所有 Search Result 和 WebDocument 固定包含：

```text
trust_level = untrusted_web_data
instruction_authority = none
approval_authority = none
can_trigger_tool = false
can_change_tool_risk = false
can_approve = false
```

此外，现有 Agent 会把 Tool result 再包装为 `trust=untrusted_data`、
`instruction_authority=none`、`approval_authority=none` 后交给 LLM。网页内的 system prompt、
Tool JSON、confirmed=true 或命令文本因此没有控制权。

## 5. URL Fetch 安全与失败语义

Direct URL 当前执行以下 fail-closed 检查：

1. 只允许 HTTP/HTTPS，拒绝用户信息 URL 和异常 host。
2. 只允许默认 Web 端口 80/443。
3. 阻断 localhost、`.local`、`.internal` 和所有非 global IP，包括 loopback、private、link-local、
   multicast、reserved、unspecified 及常见 metadata 地址。
4. 一个域名只要解析结果中含非公网 IP，整次请求即阻断。
5. transport 只连接 policy 已验证的 IP；HTTPS 仍使用原 hostname 做 SNI/证书验证。
6. 最多 3 次 redirect，每一跳重新执行完整 URL 和 DNS/IP 检查。
7. 总响应正文最多 2 MiB，只接受 HTML/XHTML/plain text，要求 identity content encoding。
8. 使用固定 GET、User-Agent、Accept 和无代理的 socket transport，不执行脚本、表单或下载附件。
9. DNS、timeout、HTTP、redirect、size、MIME、encoding 和 parser 异常返回明确错误，不生成内容。

## 6. Trace

`retrieve_web` 复用现有 Agent Tool Trace，记录：

- `event_type=tool_execution`
- `tool_name=retrieve_web`
- query 或 URL 参数
- success/failed status 和 error code
- duration/latency

Trace 的 result summary 使用现有有界摘要，不保存网页正文或模型内部推理。Search/Fetch 结果中的
完整外部内容只存在于本次 Tool result，不写入长期本地 Document/Evidence 存储。

## 8. 当前限制

1. 本阶段只提供 Search Provider 抽象，默认 provider 未配置；没有绑定具体搜索服务或 API key。
2. V5.1 不是自治浏览 Agent：不会自动遍历网站、跟随正文链接、长期爬取或根据网页内容发起下一 URL。
3. Direct URL 只处理单页 HTML/XHTML/plain text；不下载 PDF、Office、图片、音视频或附件。
4. 为降低 SSRF 和非标准服务风险，当前只允许 80/443 端口，不使用系统代理。
5. HTML parser 是确定性正文提取，不执行 JavaScript；依赖客户端渲染的页面可能正文为空。
6. 未实现 Evidence 4.0、Authority/Freshness 评分、Cross-Source Retrieval、复杂 Query Rewrite 或
   Web 内容长期存储。
7. Source Router 是策略提示，不强制覆盖 LLM Tool 选择；Python Tool Schema、URL policy 和 Safety
   仍是最终执行边界。
8. 本阶段未修改前端，Web 结果通过现有 Chat Tool result/answer 流程展示。

## 9. 阶段边界

V5.1 仅交付受控 Web Retrieval foundation。没有开始 V5.2，也没有提前建设 Evidence 4.0 或
Cross-Source Agentic Retrieval。
