# V7.3 Research Task Center

## 1. 设计目标与接口审计

V7.3 将 V6 Research Task 的状态、过程、结果和恢复操作展示为独立研究任务中心。仅修改前端及新增测试、文档；不修改 backend、Research Task Runtime、Async Runtime、Workflow、Retry 或 Resume 机制。

开发前确认原 `tasks.py` 仅包装通用 Task Center，研究任务没有独立详情页。已有接口如下：

| 方法 | API | 作用 |
| --- | --- | --- |
| POST | `/api/research-task` | 创建研究任务，继续由聊天页使用 |
| GET | `/api/research-task/{id}` | 研究状态、query、时间、阶段、结果、错误 |
| POST | `/api/research-task/{id}/cancel` | 在既有安全点取消 |
| POST | `/api/research-task/{id}/retry` | 调用原重试流程 |
| POST | `/api/research-task/{id}/resume` | 调用原恢复流程 |
| GET | `/api/sessions/{session_id}/tasks` | 持久化会话任务列表 |
| GET | `/api/tasks/{id}` | 通用任务详情，含 can_cancel / can_retry / can_resume |
| GET | `/api/tasks/{id}/traces` | 已脱敏 Trace |
| GET | `/api/evidence/{id}/locate` | 原 Evidence 定位，传入任务所属 session_id |

Research Task 路由还提供无 `/api` 前缀别名，前端统一使用 `/api`。通用 `/api/tasks` 创建和操作接口保留给原 OCR、索引、Workflow 页面组件；没有新增后端端点。

## 2. 页面结构

侧栏“研究任务”打开独立研究任务中心。

- 列表：任务名称（query）、状态、创建时间、更新时间、当前阶段和查看详情按钮。
- 筛选：全部、运行中、已完成、失败。
- Task ID 入口：打开不在当前列表范围内的已有研究任务，非法格式在前端拒绝。
- 详情：基本信息、操作按钮、实际阶段时间线、Evidence 数量、执行日志及研究结果。
- 聊天：研究任务卡增加“在任务中心打开”，携带原 task_id 切换页面，不创建新任务。
- 保留原 OCR / 索引 / Workflow 任务组件与原刷新、取消、重试、恢复能力；研究任务在专用区域展示。

列表/详情以 Streamlit `research_selected_id` 状态切换，不新增 HTTP 页面路由或前端框架。

## 3. 列表范围与数据流

后端没有全局研究任务列表接口。前端读取当前会话以及 V7.2 浏览器历史中的已知 session_id，每会话调用原列表 API，最多返回最近 100 个可见任务；识别 `research` / `async_research` 后，调用原 Research Task 查询接口读取用户级状态。

聊天消息中的 research_task_id、当前已知研究任务和手动打开过的任务也进入浏览器任务目录，以免任务因会话切换丢失入口。列表去重依赖原 task_id，不复制后端任务或生命周期。

此列表不是全局账户任务列表，也不等于永久任务历史。浏览器状态丢失后可通过已保存的 task_id 重新打开任务；不自动发现未知会话。列表读取失败会显示错误；单个任务查询失败时保留带“上次读取状态”标识的缓存，不把缓存冒充最新状态。

## 4. 状态与 Timeline

直接展示 Research Task API 的 status 和 progress.stage，包括 CREATED、RUNNING、WAITING_TOOL、COMPLETED、FAILED、CANCELLED，以及 PAUSED、WAITING_CONFIRMATION、PARTIAL_SUCCESS 等扩展状态。

- 运行中：CREATED / RUNNING / WAITING_TOOL。
- 已完成：COMPLETED。
- 失败：FAILED / PARTIAL_SUCCESS。
- 全部：包括取消、暂停和等待确认状态。

Timeline 显示任务创建时间、Trace 中 `research_stage` 的实际阶段记录，以及 API 当前阶段和状态。Trace 默认只返回最近记录，页面提示记录可能不完整。进入某阶段不等于阶段完成，所以历史阶段使用记录标记，只有整体 COMPLETED 使用完成标记；不会按预设顺序推测 Local/Web 检索已经执行，也不编造报告生成阶段。

结果尚不可用时 Local Evidence / Web Evidence 显示 `—`，避免把未知数量当成零。结果可用后，按原 Unified Evidence / 兼容 Evidence 的 source_type 统计：LOCAL/structured/unstructured 为本地，WEB/URL 为网页。结果正文、Quality Gate / Web Warning 及 Evidence 均来自原 API；不重新检索或生成证据。

## 5. 操作与自动刷新

取消、重试、恢复按钮只依据原 `/api/tasks/{id}` 的 can_* 标志启用，不在前端重新定义重试资格。权限读取失败时全部禁用。点击后调用对应 Research Task API，由后端决定能否执行；状态变化导致请求被拒绝时显示原错误，不假装操作成功。取消请求已登记时显示等待安全点停止。

自动刷新默认开启，使用 Streamlit `st.fragment(run_every=5)` 每 5 秒重新读取当前列表或详情。只在页面活跃且浏览器连接时轮询，允许关闭，仍保留手动刷新按钮。没有阻塞 sleep 循环、WebSocket、消息队列或后端定时任务。轮询只发 GET，不自动重试、恢复、取消或生成报告。

“查看执行日志”复用 Trace 组件。“查看研究结果”复用 Evidence Preview。原文定位使用任务返回的 session_id，避免打开历史任务时错误使用当前聊天会话。结果/详情/Trace 读取失败有独立提示，详情失败不展示可操作的陈旧按钮。

## 6. 修改文件

- `frontend/research_center.py`：已有会话任务发现、研究状态查询、筛选、Evidence 计数、Timeline 和操作 HTTP 调用。
- `frontend/pages/tasks.py`：列表/详情、轮询、状态与结果 UI，保留原通用任务组件。
- `frontend/pages/chat.py`：研究任务跳转入口。
- `frontend/api_client.py`：封装原 Research Task cancel/retry/resume 接口，拒绝未知操作。
- `tests/test_research_center_v73.py`：新增 UI 和接口契约测试。
- 本文档。
