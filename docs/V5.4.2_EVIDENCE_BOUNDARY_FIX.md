# V5.4.2 Security / Evidence 最终边界修正

## 1. 问题

V5.4.1 已将 `backend/evidence.py` 和
`backend/services/cross_source_retrieval.py` 恢复到稳定基线，但当时 Web
Retrieval 的调用顺序仍为：

```text
Web Record
    ↓
UnifiedEvidenceFactory
    ↓
secure_web_evidence()
    ↓
UnifiedEvidence
```

`secure_web_evidence()` 会在 Factory 返回后重新构造 UnifiedEvidence，以附加
安全 metadata 和风险模式。虽然 Schema 不变，这仍破坏了
UnifiedEvidenceFactory 作为最终统一出口的职责。

## 2. 修改前后数据流

### 修改前

```text
Web Content
    ↓
Security Detection
    ↓
Web Retrieval
    ↓
UnifiedEvidenceFactory
    ↓
Security Adapter 修改 Evidence
    ↓
UnifiedEvidence
```

### 修改后

```text
Web Content
    ↓
Security Layer
    ↓
Web Record metadata
  - untrusted_content
  - risk_patterns
  - security_flags
    ↓
Web Retrieval
    ↓
UnifiedEvidenceFactory
    ↓
UnifiedEvidence（最终对象）
```

`WebPageParser` 和 `SearchProvider` 在 Web Record 进入 Web Retrieval 前调用
`web_security_metadata()`。安全 metadata 包含：

```json
{
  "untrusted_content": true,
  "risk_patterns": [],
  "security_flags": {
    "instruction_authority": "none",
    "approval_authority": "none",
    "can_trigger_tool": false,
    "can_change_tool_risk": false,
    "can_approve": false
  }
}
```

稳定的 Web Evidence Builder 原本就会把 Web Record metadata 复制到
UnifiedEvidence metadata，因此无需修改 Evidence 模块。WebRetrievalService
现在直接返回 `build_web_evidence(...).model_dump(...)`，Factory 后不存在任何
Evidence 修改、升级或重新验证步骤。

Trace Middleware 从 `UnifiedEvidence.metadata.risk_patterns` 读取风险模式；只读
取值，不修改 Evidence。

## 3. 职责边界

### Security Layer

- 检测网页正文、标题、摘要和外部 metadata；
- 生成 `untrusted_content`、`risk_patterns`、`security_flags`；
- 不创建或修改 UnifiedEvidence。

### Web Parser / Search Provider

- 保留完整外部正文；
- 在 Web Record 阶段写入 Security Layer 生成的 metadata；
- 将已标记的中间记录交给 Web Retrieval。

### Web Retrieval

- 调用稳定的 `build_web_evidence()`；
- 直接输出 Factory 返回的 UnifiedEvidence；
- 不进行 post-Factory Evidence 适配。

### UnifiedEvidenceFactory

- 继续作为 Local、Web、URL Evidence 的唯一最终创建出口；
- Schema、Factory、Serializer 和兼容链路均未修改。

### Trace Layer

- 从 Evidence metadata 读取风险模式；
- 记录可观察的安全结果；
- 不修改 Evidence，不记录网页全文或模型内部推理。

## 4. 稳定模块确认
