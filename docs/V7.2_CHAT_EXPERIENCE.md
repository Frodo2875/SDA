# V7.2 Chat Experience Upgrade

## 1. 设计目标与已有结构

V7.2 将现有聊天组件组合成 Chat Workspace，让用户在知识库上下文中查看消息、来源和真实研究状态。不新增 Agent、Retriever、Evidence、Task Runtime、API 或依赖。

实现前审计：

- `frontend/pages/chat.py` 原先包含消息列、Evidence 列和列内输入框。
- `chat_panel.py` 已具备消息气泡、Evidence 折叠区、任务卡、Trace、Diff 和审批卡。
- `evidence_panel.py` 已支持来源及原文定位；补足 Markdown 标题/行号、表格行号、显式 Web 来源信息。
- `task_progress.py` 已展示 Workflow 任务；Research Task 使用独立的用户级 API，前端读取其状态，不复制任务执行逻辑。
- `controller.py` 管理当前 Streamlit 会话与原 Chat API 调用。
- 后端提供 Research Task、Report、会话任务、Trace 和结构化 context 接口。`/api/sessions/{id}/context` 明确不返回聊天历史，不能用于重建历史消息，也没有按知识库查询聊天列表的接口。

## 2. Chat 页面结构

顶部显示当前知识库名称、知识库选择、新建会话入口和当前知识库历史聊天。中部为三种模式选择及两列布局：左侧消息与研究结果，右侧 Evidence Preview。输入框移至两列之后，占用整个聊天区域宽度。

普通问答直接复用原 Chat API；深度研究与报告生成先创建原 Research Task，立即保留任务 ID。报告模式在研究完成后显示可用的“生成报告草稿”按钮，再调用原 Report API。草稿显示正文和后端 Warning，支持选择 md/docx 并预览申请导出，审批和版本写入继续使用原组件与 API。

没有实现报告中心、任务中心重构、流式输出或新的后端执行流程。

## 3. 知识库绑定与会话

知识库详情“新建聊天”调用统一的 `new_conversation()`：保存当前浏览器内会话快照，创建新的 session_id，绑定 knowledge_base_id/name，并清空当前消息、Evidence 和任务视图。聊天页也可加载已有知识库并选择新建会话。

会话快照保存消息、Evidence、原文定位、任务状态、知识库、模式、标题及创建/更新时间。历史列表按当前知识库过滤，显示标题、时间和最近消息，打开时恢复原 session_id，继续使用原后端会话。浏览器内会话快照不修改数据库。

**边界：**knowledge_base_id 仍是前端组织上下文，不传入不支持此字段的 Chat/Research 请求；后端尚未按库限定检索，页面明确提示。历史列表仅覆盖当前浏览器会话内记录，刷新导致会话断开或服务重启后可能丢失，不声称具备服务器持久历史或跨设备同步。由于现有 context 接口不含历史消息，本阶段不拿结构化 context 冒充完整聊天历史。

## 4. Evidence 展示

回答下方展示带编号的来源列表，保留原 Evidence 折叠区与打开原文功能。“查看本条回答证据”可将任意历史回答的证据切换至右侧。

- Local：文件名、类型、Sheet/Row、Page/Block/Cell 等原字段；Markdown 从 metadata 展示 heading_path、line_number、line_end。
- Web：URL、Domain、Retrieved At，缺失信息显示未提供，不编造抓取时间；只对有效 HTTP(S) URL 提供链接。
- 空证据显示“暂无证据。”新请求清空旧的右侧证据，防止失败请求误用上次来源。
- Quality Gate 和 Web Warning 直接展示后端返回值，不重新评估 Evidence，不改写 Schema 或生成新引用。

来源编号是展示当前回答来源的顺序，不代表新增逐句事实验证或引文映射。

## 5. Research Task 状态与 API

| 能力 | 原有 API | 前端行为 |
| --- | --- | --- |
| 普通问答 | POST `/api/chat` | 同步显示回答；复杂请求若返回 research_task_created，提供刷新入口 |
| 创建研究 | POST `/api/research-task` | 请求只含 session_id/query，保存返回 task_id |
| 查询研究 | GET `/api/research-task/{id}` | 显示真实 status、progress.stage、更新时间与失败消息 |
| Trace | GET `/api/tasks/{id}/traces` | 保留原 Trace 展示 |
| 报告草稿 | POST `/api/research-task/{id}/reports` | 仅 COMPLETED 时允许生成 |
| 导出预览 | POST `/api/research-task/{id}/reports/{report_id}/preview` | 选择 md/docx，展示原待审批动作 |
| 确认/取消 | POST `/api/actions/{id}/confirm` 或 cancel | 原审批组件、版本流程保持 |

研究状态由“刷新研究状态”读取，不虚构阶段完成标记，也不推断未返回的检索步骤已完成。任务完成时更新原消息的正文、Evidence、Warning 和待审批动作，多次刷新不会重复追加答案。任务失败或网络异常显示错误并保留任务 ID；Trace 不可用不丢弃研究结果。报告草稿仅由用户点击生成，重复页面重跑不会自动创建新草稿。

## 6. 修改文件

- `frontend/chat_workspace.py`：浏览器会话快照、模式分发、研究查询及报告草稿调用。
- `frontend/pages/chat.py`：Chat Workspace 布局、模式/知识库/历史交互、研究和报告卡片。
- `frontend/pages/knowledge.py`：复用统一新会话入口。
- `frontend/controller.py`：保留复杂聊天返回的任务 ID，辅助 API 失败不丢弃回答，清理旧证据并透传质量警告。
- `frontend/api_client.py`：封装已有研究/报告 API。
- `frontend/components/chat_panel.py`：编号来源、回答证据选择和已有质量警告。
- `frontend/components/evidence_panel.py`：定位字段和 Local/Web 卡片展示。
- `tests/test_chat_experience_v72.py`：新增交互及 HTTP 契约回归测试。
- 本文档。

## 7. 测试

Streamlit AppTest 覆盖普通聊天、三种模式、任务创建/阶段/结果/失败、报告完成条件与审批入口、知识库选择、历史恢复与分组、历史 Evidence 切换、网络异常处理。纯函数测试覆盖 Markdown/表格定位、来源标签和不可点击 URL；HTTP 契约测试确认复用现有接口且未添加不支持的知识库请求字段。

V7.1 原有“从知识库进入聊天并携带 knowledge_base_id”的测试继续执行；V7.0 的消息/Evidence/Trace 跨页访问、原文件工作台和 V6 回归均保留。没有删除或降低旧测试断言。

全量 `pytest -q`：**730 passed，0 failed，0 skipped，61.92 秒**。V7.1 基线 708 项，本次新增 22 项。旧测试文件未修改。

首次全量发现 V5 定位摘要要求保留 `Retrieved：` 标签，已在前端恢复兼容格式；新卡片仍单独展示 Retrieved At。修正后重新执行完整回归并全部通过。

## 8. 验收与后续边界

backend 零修改。当前可以验收知识库上下文 → Chat Workspace → 原 Agent/Research → Evidence/报告的交互链路。后续 V7.3 可以在既有边界下推进；如要求跨设备持久历史或按库检索，应先独立明确后端接口方案。本阶段没有开发 Research Task Center，也不创建 tag。
