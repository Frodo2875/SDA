# V5.2 Evidence 4.0 开发记录

## 1. 实现目标

V5.2 将 V4 的本地 Evidence 3.0 与 V5.1 的 Web Tool Result 接入同一个
Unified Evidence System，正式支持：

- `LOCAL`：本地 PDF、Word、Excel、CSV、图片/OCR、PPT、TXT、JSON；
- `WEB`：Search Provider 返回的公开网页摘要；
- `URL`：用户明确 URL 经安全 Fetch 与 Web Parser 得到的网页正文。

Evidence 仍然只描述“内容来自哪里”，不保证内容真实。Evidence 只能由 Parser、
OCR、结构化查询、Retrieval、Search Provider 或 URL Fetch 的程序输出生成，模型不能
创建 Evidence。

## 2. Evidence 3.0 到 4.0 的变化

Evidence 3.0 的 `source_type` 已有稳定含义：`structured` 或 `unstructured`，且既有
Tool 和测试依赖其精确返回字段。V5.2 没有覆盖或删除这套契约，而是新增版本化的
`UnifiedEvidence`：

| 字段 | Evidence 3.0 | Evidence 4.0 |
| --- | --- | --- |
| `evidence_version` | `2.0/3.0` | `4.0` |
| `source_type` | `structured/unstructured` | `LOCAL/WEB/URL` |
| 统一内容 | `value_summary/text_excerpt` | `content` |
| 本地定位 | file/page/block/table/cell/bbox 等 | 原字段全部保留 |
| Web 定位 | 不支持 | url/domain/title/publisher |
| 时间 | 不支持 | published_at/retrieved_at/freshness |
| 来源属性 | 不支持 | authority |
| 扩展信息 | 部分专用字段 | `metadata` |

本地升级后使用 `legacy_source_type` 保存原有 `structured/unstructured` 语义。

## 3. Schema 设计

`backend/evidence.py` 新增 `UnifiedEvidence`，公共字段包括：

- `evidence_id`
- `evidence_version=4.0`
- `source_type=LOCAL|WEB|URL`
- `content`
- `authority=official|academic|general|unknown`
- `freshness=published_at_available|retrieval_time_only|not_applicable`
- `metadata`

Local Evidence 保留 Evidence 3.0 的 file、sheet、page、image、chunk、block、region、
table、cell、row/column、line、JSON Path、slide、bbox、confidence、OCR/手写、冲突和
人工核对字段。

Web/URL Evidence 增加：

- `url`
- `domain`
- `title`
- `publisher`
- `published_at`
- `retrieved_at`

Web/URL Evidence 必须同时满足不可信数据约束：

- `trust_level=untrusted_web_data`
- `instruction_authority=none`
- `approval_authority=none`
- `can_trigger_tool=false`
- `can_change_tool_risk=false`
- `can_approve=false`

Schema Validator 会拒绝缺少本地文件来源的 `LOCAL` Evidence，以及缺少 URL、domain、
retrieved_at 或不可信标记的 Web Evidence。

## 4. Evidence 生成链路

### Local

```text
Document Parser / OCR / Table Query / Local Retrieval
    -> Evidence 3.0（原契约）
    -> deterministic upgrade_local_evidence
    -> Evidence 4.0 LOCAL
```

升级器只复制真实的 Evidence 3.0 内容和定位字段，不调用模型、不补造内容。

### Web Search

```text
Search Provider result
    -> normalize_search_results
    -> build_web_evidence
    -> Evidence 4.0 WEB
```

只有真实 snippet 才能形成 Evidence。只有 URL、没有摘要的 Search Result 仍可作为候选
返回，但不会被当作证据。

### Direct URL

```text
URLFetcher
    -> WebDocument
    -> build_web_evidence
    -> Evidence 4.0 URL
```

Web Retrieval 不再把完整 `WebDocument` 作为 Tool Result 返回；返回正式
`evidence/evidence_chain`。Evidence 正文最多保留 12,000 字符，是否截断记录在
`metadata.content_truncated`，避免把超长网页原样送入后续链路。

## 5. Authority 与 Freshness

Authority 不是真实性评分：

- 只接受来源适配器显式提供的 `official/academic/general/unknown`；
- 缺失、非法或无法识别时固定为 `unknown`；
- 不根据域名、标题或网页正文猜测。

Freshness 是可解释时间状态，不是真实性判断：

- 有显式 `published_at`：`published_at_available`；
- 无发布时间但有真实抓取时间：`retrieval_time_only`；
- 本地 Evidence：`not_applicable`。

`published_at` 缺失时保持空值，`retrieved_at` 由程序在检索完成时写入 UTC 时间。

## 6. 兼容策略

1. `Evidence`、`build_evidence()`、Evidence Location 数据库及旧 Tool Result 不变；
2. API `evidence` 字段继续保持旧契约；
3. API 新增 `unified_evidence`，所有本地、Web、URL 证据均可按 4.0 表示；
4. 混合 Tool Chain 出现 Web/URL 时，Answer Evidence 会把本地证据确定性升级为
   `LOCAL`，保证同一链内 Schema 统一；
5. 会话上下文只保存有限 Evidence 引用，不保存网页正文；
6. Trace 只记录 Web Evidence ID、来源类型、数量、状态和模式，不记录网页正文；
7. 前端 Evidence Panel 优先展示 `unified_evidence`：本地来源继续打开原文定位，
   Web/URL 显示 title/domain/publisher/time/authority 并提供来源链接。

没有数据库 migration，也没有修改 Source Router、Tool Boundary、Web Parser、Search
Provider 或 Agentic Retrieval。

## 9. 当前限制

- Authority 仅接受显式来源属性，不做站点真实性认证；
- Freshness 不计算分数，也不判断内容是否仍然有效；
- Search Result Evidence 使用 Provider snippet，不自动 Fetch 每个结果正文；
- Direct URL Evidence 仅覆盖单次受控 Fetch，不做网页遍历或长期爬取；
- Web Evidence 不写入本地 Evidence Location 表，通过 URL Citation 回到来源；
- 未实现 Cross-Source Retrieval、Query Rewrite、Evidence Sufficiency、Graph RAG 或
  多轮 Agentic Web Retrieval。
