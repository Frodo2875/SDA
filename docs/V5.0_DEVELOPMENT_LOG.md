## 1. 实现目标

V5.0 在 V4 冻结架构上增量增加 PPT/PPTX、TXT、JSON、CSV 正式 Document 支持。新格式继续
使用现有文件注册、Input Router、Document Lifecycle、DocumentBlock/Chunk、结构化 Schema、
Hybrid Retrieval、Evidence 3.0、Async Task 和 Workspace 后端接口，没有建立独立处理系统。

本阶段未实现 Web Search、URL Fetch、Evidence 4.0 或 Cross-Source Agentic Retrieval，未修改
Agentic Retrieval 和前端视觉系统。

## 2. 新增模块

### `backend/services/multiformat_parser.py`

提供有界、确定性的本地格式解析：

- TXT：支持 UTF-8/UTF-8 BOM、UTF-16 BOM、GB18030/GBK、Big5；按非空行生成
  DocumentBlock，并保留 `line_number` 和 encoding。
- JSON：支持 object、array 和 nested object；用 `$` 根路径及 dotted/bracket path 保留结构，
  每个叶节点生成 Block，并保留 `json_path`。
- CSV：使用 Python `csv` 做 dialect/header/row 解析和标量类型归一化，保留二维结构，不转成
  普通文本。
- PPTX：使用标准库 ZIP/XML 读取 slide 文本和基础表格，保留 `slide_number`、table/row/column。
- PPT：验证 OLE CFB header，保守读取 PowerPoint text atom，并保留基础 slide 编号。
- 所有 parser 都有文件大小、解压大小、条目、文本长度、CSV 行列、JSON 深度/节点等安全上限。

统一解析结果包含 `document_id`、`file_name`、`content`、`block`/`blocks` 和 `metadata`，随后
转换到 V4 `DocumentBlock` 和 `document_chunks`。

### 3.1 生命周期与索引语义

- TXT/JSON/PPT/PPTX：上传校验后经过既有 DETECTING/PARSING，随后由统一索引候选构建、
  INDEXING 和原子 QUERYABLE 激活，`index_status=indexed`。
- CSV：遵循既有 Excel 结构化路径，Schema 解析成功后 `parse_status=parsed`、`queryable=true`，
  `index_status=not_required`；其“索引”是现有 `table_schemas/schema_fields` 结构化 Schema，而非伪造
  document chunk。
- reindex/reprocess 继续由既有 Document service 和 Async Task 调用，失败时不破坏旧活动索引。

### 3.2 Evidence 兼容

Evidence 版本仍为 3.0，没有实施 Evidence 4.0。新增字段均为可选字段：

- TXT：`locator_type=txt`、`line_number`；
- JSON：`locator_type=json`、`json_path`；
- PPT/PPTX：`locator_type=presentation`、`slide_number`；
- CSV：`locator_type=csv`、`row_number`、`column_name`，并继续提供 table/cell/field/record key。

Excel、Word、PDF、图片及视觉表格的旧 Evidence shape 和 legacy projection 保持不变；完整 V4
Evidence 专项回归通过。

## 5. 已知限制

1. PPTX 当前覆盖 slide 文本和基础 DrawingML table，不处理动画、SmartArt、复杂视觉布局、图表
   推理和嵌入对象。
2. 仓库不存在 Notes 统一架构，因此本阶段未新建 Notes 子系统；PPTX notes 留待后续明确需求。
3. 旧 PPT 使用保守的 OLE 内 PowerPoint text atom 提取；复杂表格、布局和跨 sector 的异常文件
   可能无法完整恢复，失败时返回可解释错误，不调用 LLM 猜测。
4. CSV 要求首行为非空且唯一表头，支持常见 delimiter；不执行公式，空值保持 `None`，最大
   100,000 数据行、500 列。
5. JSON 最大 64 层、200,000 节点；key 不符合 identifier 时使用 bracket path；不接受 NaN、
   Infinity 等非标准常量。
6. TXT 编码识别是确定性白名单，不使用 LLM；白名单之外的编码会安全拒绝，避免乱码进入索引。
7. 本阶段不修改前端，因此新类型使用现有通用 Workspace/Preview 渲染能力，没有新增专用 slide、
   JSON tree 或 CSV 可视化组件。

## 6. 阶段边界

V5.0 只交付多格式本地 Document 支持。Web Retrieval、Direct URL、Evidence 4.0、Cross-Source
Agentic Retrieval 和 Web Safety 属于后续阶段，本阶段没有提前开发。
