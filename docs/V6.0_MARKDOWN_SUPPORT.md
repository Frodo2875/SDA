# V6.0 Markdown 正式 Document 支持

## 1. 开发背景

阶段：V6 Phase 1。分支：`feature/v6-development`。
开发起点：`98e87a4`（Phase 0 文档提交），V5 冻结基线为 `36ccc19`。
V5 已提供多格式文档、检索、Unified Evidence 4.0 与安全边界；本阶段只新增 Markdown 输入适配。

Phase 0 曾建议将 Markdown 归入 TXT 子格式。本轮正式要求独立 Markdown Document Type，
因此 `.md`、`.markdown` 均注册为 `file_type=markdown`，不再采用 TXT 别名。
前端、研究任务、质量 Gate、Web Reliability、Report 等不在本轮范围。

## 2. 为什么 V6 补充 Markdown

项目说明、安装指南、研究笔记常以 Markdown 保存。将其接入现有文档体系，
可以在检索时保留标题层级和原始行位置，为后续研究引用提供来源依据。
本轮提供资料输入与证据能力，不建设 Markdown Workspace、Editor 或 Renderer。

## 3. 架构流程

```text
.md / .markdown（保留原文件名，扩展名不区分大小写）
 -> File Type Router：markdown / TEXT
 -> 既有上传验证、文件注册与 Document Lifecycle
 -> parse_local_document -> parse_markdown
 -> ParsedDocument / DocumentBlock / metadata_by_block
 -> 既有 blocks_to_chunks / Index 原子激活
 -> 既有 hybrid_retrieve / LocalHashEmbeddingProvider / reranker
 -> UnifiedEvidenceFactory.local
 -> 在现有 metadata 字典中补充 Markdown 定位字段
 -> Unified Evidence 4.0 + 既有 Evidence 3 兼容响应
 -> locate_evidence 按来源 Chunk 返回标题路径和行范围
```

没有新增 Retriever、队列或 Evidence 版本。异步 index/reindex/layout 只增加文件类型白名单，
仍由原 handler 处理。CSV、TXT、JSON、PDF、Word、图片和演示文稿原分支保持原行为。

## 5. Parser 设计

采用 Python 标准库实现明确的 Markdown 输入子集，不执行渲染，不新增第三方依赖。
当前需求是有限的块识别及来源映射，不需要完整 CommonMark/GFM 渲染能力，
因此本轮不引入 markdown-it-py 或 mistune。未来若要求完整规范，应另行评估库的源码位置映射、
扩展语法、安全选项和依赖成本，不能把当前子集声明为完整 CommonMark 兼容。

| 输入 | 解析策略 |
| --- | --- |
| ATX 标题 `#` 至 `######` | 保留标题内容及 level；遇同级/更高标题弹出旧层级，生成 heading_path |
| 普通段落 | 按空行或新块边界划分，保留块内换行 |
| 无序/有序列表 | 保留 `-`、`+`、`*`、数字 `.`/`)` 和缩进；不转换为 HTML |
| Pipe 表格 | 识别对齐分隔行，支持示例中的单横线及转义 pipe；使用现有 table Block 和 `build_simple_table` / `TableStructure` |
| 不规则表格 | 保留原始文本和 table Block，标记 degraded/IRREGULAR_MARKDOWN_TABLE，不猜测缺失单元格 |
| 反引号/波浪线 fenced code | 保存 language、精确块内文本；忽略块内标题/链接语法；未闭合时保留文本并给出警告 |
| 简单内联链接 | 保存 text、URL；原 Markdown 文本保留；不访问 URL |
| HTML / 图片语法 | 按不可信资料文本保留，不渲染、不加载资源 |

复用 `decode_text_file` 支持 UTF-8/BOM、UTF-16 BOM、GB18030/GBK、Big5，拒绝二进制控制字符。
沿用 20 MiB 文件和 5,000,000 字符限制，新增 100,000 行、20,000 块、单表 20,000 单元格上限。
解析错误使用 `MultiFormatParseError`，上传沿用 `INVALID_FILE_CONTENT`，重建失败沿用原索引保护。
空文件、全空白和只有空代码围栏的文档拒绝入库；有正文的文档可保留空代码 Block，索引时排除空 Chunk。

## 6. Block 设计

不更改 `DocumentBlock` Schema。标题使用 `title`，段落/列表/代码使用 `paragraph`，表格使用 `table`。
更细的语义放入既有 `ParsedDocument.metadata_by_block`，由 Chunk metadata 持久化：

```json
{
  "document_format": "markdown",
  "heading_path": ["项目说明", "安装方法"],
  "line_number": 4,
  "line_end": 5,
  "block_type": "markdown_paragraph"
}
```

语义类型包括 markdown_section、markdown_paragraph、markdown_list、markdown_table、markdown_code。
`metadata.block.block_type` 保留规范 Block 类型；`metadata.block_type` 为 Markdown 语义类型。
代码附带 language/content，链接附带 links，规则表格附带既有 TableStructure 序列化结果。
稳定 Block/Chunk ID 和切分仍由现有工具生成，不同位置的同名标题不会合并为一个块。

## 7. Evidence 定位设计

检索仍调用 `UnifiedEvidenceFactory.local` 创建真实来源及安全字段。随后只在其既有 metadata
字典补充 `document_format/heading_path/line_number/line_end/block_type`，保留 Factory 的
`legacy_evidence_version`，不绕过工厂，不改 Schema、Evidence ID 或不可信权限。

规范响应通过 `unified_evidence` 返回，例如：

```json
{
  "evidence_version": "4.0",
  "source_type": "LOCAL",
  "file_name": "example.md",
  "line_number": 4,
  "metadata": {
    "legacy_evidence_version": "3.0",
    "document_format": "markdown",
    "heading_path": ["项目说明", "安装方法"],
    "line_number": 4,
    "line_end": 5,
    "block_type": "markdown_paragraph"
  }
}
```

以上为省略其他字段的示意片段。Evidence 3 兼容投影不新增字段，原 `locator_type`
允许为 None，依靠 file_id/chunk_id/block_id 保持可定位；不新增 markdown locator 枚举。
`locate_evidence` 从已保存的 Evidence ID 和活动 Chunk metadata 获取标题路径、行号及正文，
无需更改 Evidence repository 或旧模型。

行号从 1 开始、结束行包含在范围内，指整个源 Block。长块切分后仍保留源 Block 范围；
精确引用用 Chunk ID，不能将块起始行误称为命中子串的精确行。Markdown 定位优先精确匹配 Chunk，
不因同一 Block 的首块匹配而指向错误文本；重建后旧 Chunk 已不存在时返回不可定位。

检索可使用既有 file_id/file_ids scope，或 `document_metadata={"document_format":"markdown"}`。
为保持 Tool Boundary 未修改，`RetrievalScope.file_type` 不增加 markdown 枚举；
文件列表 API 的 `file_type=markdown` 与检索工具的 scope 是不同接口。

## 9. 限制与交付边界

- 不保证完整 CommonMark/GFM 兼容；Setext 标题、引用式链接、复杂嵌套链接/pipe 代码语法、缩进代码块等未结构化语法按原文保留。
- 列表保留文本与缩进，不构造独立列表 AST；代码 language 不代表可执行权限。
- 表格复用现有结构，但本阶段不提供 Markdown 专用表格计算或单元格检索工具。
- 不新增 Markdown 页面、在线预览或编辑器。新增的后端来源定位是 Evidence 必要能力，不是 Markdown 渲染。
- 全量测试使用既有临时数据库和离线 Provider，不代表在线搜索验证。
- 仅完成 Phase 1；不开展 Research Task、Quality Gate、Web Reliability 或 Report 开发。
- 按要求提交 `V6.0 markdown document support`；本轮不创建 tag，交由人工验收。
