# V5.3 Cross-Source Agentic Retrieval 开发日志

## 1. 架构设计

V5.3 在 V4 本地 Agentic Retrieval 之上新增跨来源协调层，不重写已有
RAG、Web Retrieval、Source Router、Tool Boundary 或 Evidence Factory。

执行链路为：

```text
结构化 Information Need（LLM 可填写，Python 严格校验）
    ↓
现有 route_source()
    ↓
SourcePlan（LOCAL / WEB / BOTH / DIRECT_URL）
    ↓
现有 resolve_source_tool_scope() + Safety Policy
    ↓
retrieve_document / retrieve_web
    ↓
仅接收 UnifiedEvidence
    ↓
规则式 Evidence Sufficiency
    ↓
充分则停止；不足时在预算内切换来源或改写一次查询
```

`BOTH` 采用 Local First。只要本地 Unified Evidence 满足明确条件，就立即
停止，不调用 Web；本地不足时才允许 Web 补充。`LOCAL` 不会越界调用 Web，
`WEB` 不会调用 Local，`DIRECT_URL` 只使用路由提取并验证过的显式 URL。

## 2. 模块变化

### 新增模块

- `backend/services/cross_source_retrieval.py`
  - `CrossSourceInformationNeed`：结构化信息需求。
  - `SourcePlan`：现有 Source Router 决策的执行表示。
  - `CrossSourceBudget`：轮次、Tool 调用量、超时和 top-k 上限。
  - `evaluate_evidence_sufficiency()`：仅依据 Evidence 数量、明确字段和明确词项判断。
  - `rewrite_query()`：最多三种确定性查询形式，不扩大 URL 范围。
  - `merge_unified_evidence()`：严格验证并按 `evidence_id` 合并 Evidence 4.0。
  - `run_cross_source_retrieval()`：跨来源受控循环和 Trace 入口。

### 接入位置

- `backend/services/document_agent_core.py`
  - 新增 `run_cross_source_retrieval()`，作为 General Document Agent Core 的统一入口。
- `backend/services/student_domain_adapter.py`
  - 扩展 `DocumentCorePort` 并透传同一 Core 能力，没有复制学生领域检索实现。

未新增 LLM Tool，未修改 Tool Registry。这样避免绕过 V5.1.1 已冻结的 Tool
Boundary；协调器每次实际调用前仍使用现有 `resolve_source_tool_scope()` 和
`source_tool_violation()` 做程序级校验。

## 3. 检索流程

1. LLM 或上层 Planner 可提供结构化 `CrossSourceInformationNeed`；Python 用
   Pydantic 校验，拒绝额外字段、空字段和无界参数。未提供时使用保守的确定性
   fallback，不生成事实。
2. `plan_sources()` 必须调用现有 `route_source()`，不维护第二套路由规则。
3. 程序根据策略确定顺序：
   - `LOCAL`：Local；
   - `WEB`：Web；
   - `BOTH`：Local → 必要时 Web；
   - `DIRECT_URL`：仅显式 URL。
4. 每次调用前执行 Tool Scope 和 Safety Policy 检查。
5. Local/Web/URL 返回值只从 `unified_evidence` 读取，并通过
   `UnifiedEvidence.model_validate()` 严格验证；旧 Evidence 3.0 不会在本流程
   中升级成主对象。
6. 充分性只检查 `minimum_evidence`、`required_fields` 和 `required_terms`。
   不使用 LLM 真假判断、Authority 智能评分或复杂 Ranking。
7. 不充分时使用确定性改写并继续；相同 Source + Query/URL 指纹不会执行两次。

## 4. 预算控制

默认预算：

- 最大轮次：3；
- 最大 Tool 调用：4；
- 总超时：10 秒；
- 单次 top-k：5。

所有上限由 `CrossSourceBudget` 校验，并设硬上界。终止原因包括：

- `SUFFICIENT`；
- `BUDGET_EXHAUSTED`；
- `TIMEOUT`；
- `NO_NEW_EVIDENCE`；
- `LOOP_PREVENTED`；
- `QUERY_EXHAUSTED`；
- `SOURCES_EXHAUSTED`。

每轮 Trace 只记录 source、tool、query/URL、状态、延迟、Evidence 数量和充分性
状态迁移；不记录模型内部推理。

## 5. 测试结果

新增 `tests/test_cross_source_agentic_retrieval_v53.py`，覆盖：

1. Local 足够时不调用 Web；
2. Local 不足时改写查询并调用 Web；
3. Web 任务直接使用 Web；
4. Direct URL 只获取显式 URL；
5. Evidence 不足时继续并合并 Local + Web；
6. Tool 调用预算耗尽时停止；
7. 重复查询循环防护；
8. 总超时停止。

定向测试：`42 passed`。

完整回归：`449 passed`。

## 6. 当前限制

- Information Need fallback 只提取少量明确字段；复杂语义应由上层 LLM/Planner
  生成结构化输入，Python 仅负责校验和执行。
- Query Rewrite 是最多三轮的确定性关键词调整，不是复杂语义改写。
- Sufficiency 表示“满足声明的证据条件”，不表示来源内容真实。
- 不包含自动爬站、长期任务、多 Agent、Graph RAG、Knowledge Graph 或复杂排序。
- Search Provider 仍由 V5.1 抽象注入；测试完全使用 fake provider/retriever，
  不依赖实时互联网。
