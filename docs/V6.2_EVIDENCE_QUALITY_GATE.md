# V6.2 Evidence Quality Gate

## 1. 设计背景与目标

V6.1 已支持研究任务异步运行、状态查询和结果保存。任务完成并不说明来源字段齐全、结论已关联证据，或者不同来源没有显式冲突。V6.2 在交付前增加确定性检查，将这些缺口保存为可查询的 warnings。

本阶段继续使用 Unified Evidence 4.0，不新增 Evidence Schema，不调用 LLM 判断真假，不输出 truth_score、accuracy_score 或可信百分比。PASS 仅表示本模块的结构与关联检查没有发现 warning，不代表结论已被事实验证。

## 2. 架构位置

```text
现有 Agent / Workflow / Retrieval
    ↓
UnifiedEvidenceFactory → Unified Evidence 4.0 + Answer Draft
    ↓
evaluate_evidence_quality（只读、确定性）
    ↓
原 Answer / 待审批报告草稿 + evidence_quality
    ↓
同步 ChatResponse / Research 结果保存 → COMPLETED
```

检查需要 Answer Draft，因此发生在草稿产生、证据收集之后，最终响应返回或任务结果保存之前，不是生成草稿前的语义审查。现有检索充分性检查继续负责检索过程中的补检索；本模块不触发补检索，不改变 Runtime 的执行决策。

`evaluate_evidence_quality(answer_draft, evidence, query=..., claim_evidence_map=...)` 为独立入口。`attach_evidence_quality(result, query=...)` 复制结果字典并添加质量信息，不改写 answer 或 Evidence。存在待审批操作的非空 `pending_action.content` 时检查该草稿，否则检查 answer。

## 3. 检查规则

| 范围 | 确定性规则 |
| --- | --- |
| Evidence 基本字段 | evidence_id 非空且不重复，evidence_version 为 4.0，content 非空，source_type 有效 |
| LOCAL 来源 | file_id、file_name 非空，并具有现有定位字段 |
| LOCAL 定位 | 接受 chunk_id、block_id、json_path、正整数页/行/幻灯片/图片序号、metadata.heading_path 或 line_number、表格单元格、结构化记录定位、区域及 bbox |
| WEB / URL 来源 | url、domain、retrieved_at 齐全；URL 为带主机名且不含凭证的 HTTP(S) 地址，域名与主机一致；不访问网络 |
| 时效性 | 当前、最新、今日、今天、实时、目前，以及 current/latest/today/up-to-date 等查询检查 retrieved_at；缺失仅警告。已有时间值检查 ISO 日期时间格式，published_at 不替代 retrieved_at |
| 显式冲突 | 相同 field、record_key、year、period、unit 范围的 LOCAL 与 WEB/URL 比较显式 metadata.value 或 value_summary；数值 100 与 100.0 等价，其他不同标量值警告；同时保留既有 conflict 标记 |
| 结论覆盖 | 按句子/换行拆分草稿，忽略 Markdown 标题和纯分隔行；优先使用传入的精确结论映射，再使用 `[evidence:ID]` / `[ID]`，否则匹配去空白、统一大小写后的原文片段；无法关联可用证据则警告 |

现有代码没有回答级 claim–evidence mapping。可选映射参数只提供轻量关联入口，不建立第二套 Evidence 存储。引用 ID 必须存在于结构有效的证据中，未知 ID 不会通过原文匹配补救。映射或引用只说明关联关系，不证明引用支持该结论。

不同记录、年份或单位不进行跨范围比较。双方都没有记录范围时，同名字段差异仅代表潜在冲突；不选择正确来源、不合并或覆盖值。

## 4. 输出与 Warning 设计

回答原正文保持不变，新增独立字段，例如：

```json
{
  "evidence_quality": {
    "rule_version": "6.2",
    "passed": false,
    "status": "WARNING",
    "warnings": [{
      "code": "EVIDENCE_MISSING",
      "message": "部分结论没有关联到可用 Evidence，请核对引用。",
      "evidence_ids": [],
      "claim_ids": ["claim-2"],
      "fields": []
    }],
    "checked_evidence_count": 1,
    "coverage": {
      "checked_claim_count": 2,
      "claim_evidence": [
        {"claim_id": "claim-1", "evidence_ids": ["local-1"], "method": "exact_excerpt"},
        {"claim_id": "claim-2", "evidence_ids": [], "method": "exact_excerpt"}
      ]
    }
  }
}
```

| Warning code | 含义 |
| --- | --- |
| EVIDENCE_MISSING | 结论没有关联可用证据，或包含未知/不可用引用 |
| SOURCE_INCOMPLETE | 来源字段缺失或 URL/domain 格式无效 |
| LOCATION_MISSING | LOCAL 缺少有效定位字段 |
| FRESHNESS_MISSING | 时间敏感查询缺少 retrieved_at |
| FRESHNESS_INVALID | 已提供 retrieved_at，但格式无法解析 |
| EVIDENCE_CONFLICT | 同一范围显式值不同，或存在已有冲突标记 |
| EVIDENCE_INVALID | 标识重复/缺失、版本或内容无效 |
| ANSWER_DRAFT_MISSING | 没有可检查的草稿结论 |
| QUALITY_INPUT_LIMIT | 输入超过检查上限，不能将未检查部分视为通过 |

同类 warning 合并，附相关 evidence_ids、claim_ids、fields，不将原始来源正文、URL 或字段值复制进警告信息。任一 warning 使 passed=false、status=WARNING；无 warning 为 PASS。质量状态不是任务状态。

## 5. Research Task 集成

`run_agent` 收集 Unified Evidence 后、存储对话及返回结果前附加质量信息。`ChatResponse` 仅新增可选的 evidence_quality 字段，Evidence Schema 不变。

Research 的 `execute_research` 在既有成功状态检查之后、`update_research` 保存结果之前调用相同模块，将 evidence_quality 纳入既有脱敏结果字段。正常 Agent 路径的重复检查是确定性的；Research 入口独立检查也覆盖返回结果尚未附加质量信息的执行器。

WARNING 不改变 Agent 成功状态，不转换为 FAILED，不触发 Retry，不阻止 COMPLETED。Research 沿用现有结果持久化与查询 API，无数据库迁移；Async Runtime、Workflow、Checkpoint、Retry、Resume、取消和去重机制均未改动。待审批内容仍走原审批流程，PASS 不授予写入权限。

## 8. 限制说明

- 不检查语义蕴含、来源真实性或答案真假；正确 ID 的引用仍可能与结论语义不符。PASS 不能作为事实正确性的证明。
- 原文匹配较保守，改写、综合分析、礼貌语句及复杂 Markdown 可能出现 EVIDENCE_MISSING。没有 LLM 结论提取或语义覆盖分数。
- 定位检查只验证字段存在及基本格式，不重新查询数据库或打开文件验证目标仍可访问；URL 检查也不替代现有 SSRF/Web Safety 边界。
- 时效检查验证 retrieved_at 是否存在/可解析，不设置统一过期时间，不保证资料仍然有效。
- 冲突检测依赖显式字段与上下文，不从自然语言抽取事实，不做单位换算。同范围标量差异只是核对提示。
- 最多检查 1,000 条 Evidence、200 个草稿片段、100,000 个草稿字符；超限给出 QUALITY_INPUT_LIMIT。原文匹配使用每条 Evidence 前 50,000 字符，后续内容可能无法建立关联而产生覆盖警告。
- 本阶段没有前端展示、自动补证、报告模板或新的任务进度阶段；不进入 V6.3。
