# V7.0 Frontend Product Foundation

## 1. 目标与基线

V7.0 为现有 Streamlit 应用建立统一产品外壳、导航和页面结构。基线为 `feature/v7-development` 上的 `f0cebeb` / `v6-final-stable`，原有 666 项测试。本阶段没有新增后端接口、业务服务或前端框架。

范围是前端页面组织和展示；知识库、报告中心、使用统计只提供导航占位。Workspace 和用户区域展示“默认 Workspace / 本地用户”，不表示已经实现工作空间切换或账号登录。

## 2. 旧结构与问题

原 `frontend/app.py` 同时负责 `st.session_state` 初始化、HTTP 回调和完整三栏界面。Document Workspace、Agent Chat、Evidence Preview、Task Center 都由入口直接渲染，用户缺少独立功能导航和首页概览。

已有组件通过回调交互：文件操作生成待审批对象，聊天区域展示审批卡片；聊天结果携带 Evidence、Task 和 Trace；状态统一保存在浏览器会话中。

## 3. 新 Layout

```text
app.py
  ├─ Header：项目名称 / 当前 Workspace / 用户区域
  ├─ Sidebar：固定八项导航
  └─ Main：按 active_page 渲染
      ├─ Dashboard（默认首页）
      │   ├─ 概览：指标、快捷入口、最近活动
      │   └─ 快捷工作台：原三栏完整入口
      ├─ Chat：消息、审批、Trace、Evidence
      ├─ Documents：原 Document Workspace
      ├─ Tasks：原 Task Center
      ├─ Settings：只读工作空间信息
      └─ Placeholder：知识库 / 报告中心 / 使用统计
```

首页保留“快捷工作台”标签，确保既有功能和操作入口完整可访问；独立导航页面则用于新的产品结构。该兼容入口复用已有组件，不维护第二套业务逻辑。

统一视觉由 `shell.py` 提供：蓝色主操作按钮、浅色侧栏、中性边框卡片、统一字体与间距。采用 Streamlit 原生按钮、容器、指标卡片和响应式列，不加入动画或第三方 UI 依赖。

## 4. 导航与状态

Sidebar 菜单：

1. 首页
2. 新建聊天
3. 知识库
4. 我的文档
5. 研究任务
6. 报告中心
7. 使用统计
8. 系统设置

使用 `st.session_state.active_page` 保存选中区域，未知路由回退首页。菜单按钮和首页快捷按钮都经过同一个 `navigate` 函数。

入口使用 Streamlit 的显式 `st.navigation`，隐藏其默认导航并禁用 `pages/` 自动发现；实际区域选择由自定义 Sidebar 管理。这里实现的是会话内页面切换，不提供独立 URL 深链接。依据 [Streamlit navigation 文档](https://docs.streamlit.io/develop/api-reference/navigation/st.navigation)，入口负责公共框架，选中的页面通过 `.run()` 执行。本轮环境 Streamlit 为 1.61.1。

原 HTTP 回调迁入 `controller.py`，继续使用 `api_client.py`。消息、session_id、任务、Evidence、文件筛选状态跨页面保留；初始化时重新绑定现有键，避免条件渲染中的组件清理导致状态丢失。

“新建聊天”是聊天区域入口：没有历史聊天时可开始提问；已有会话不会因导航而清空。多会话创建、历史会话列表和恢复留待后续阶段。

文档页产生删除/版本待审批操作时，导航到聊天页展示原审批卡片。审批仍由现有后端执行，前端不自行写入文件。

## 5. 页面与文件结构

```text
frontend/
├── app.py                 入口与页面分派
├── controller.py          原状态初始化及 HTTP 回调
├── shell.py               Header、Sidebar、导航与样式
├── api_client.py          原 HTTP 客户端，未修改
├── pages/
│   ├── __init__.py
│   ├── dashboard.py       概览与最近活动
│   ├── chat.py            聊天、Evidence、审批和 Trace
│   ├── documents.py       文档工作区
│   ├── tasks.py           原任务中心
│   ├── settings.py        只读设置占位
│   ├── placeholder.py     尚未开放区域的统一占位
│   └── workspace.py       原工作台兼容布局
└── components/            原组件，内部逻辑未修改
```

新增 `tests/test_frontend_foundation_v70.py` 与本文档；业务实现修改仅位于 `frontend/`。没有创建知识库数据库、独立报告业务页面或新 API。

## 6. Dashboard 数据边界

| 展示项 | 数据来源 / 当前表现 |
| --- | --- |
| 知识库数量 | “—”，尚未接入 |
| 文件数量 | 原 `api_client.list_files()` 无筛选调用；独立于文档页搜索条件 |
| 任务数量 | 当前浏览器会话 `known_tasks` 已加载数量；不是全系统任务总数 |
| 报告数量 | “—”，报告列表尚未接入 |
| 最近聊天 | 当前会话最近三条用户消息 |
| 最近任务 | 当前会话最近载入的三条任务及状态 |
| 最近报告 | 明确显示尚未接入 |

概览提供刷新按钮。读取文件列表失败时显示“—”和错误提示；不会把无法读取的数据伪装成零。概览暂不自动轮询，也不新增后端聚合统计接口。

## 7. 组件迁移

| 原组件 | 新位置 | 行为 |
| --- | --- | --- |
| Document Workspace | 我的文档 / 首页快捷工作台 | 原上传、筛选、预览、索引、删除与版本入口 |
| Agent Chat | 聊天 / 首页快捷工作台 | 原消息提交和结果展示 |
| Evidence Preview | 聊天右侧 / 首页快捷工作台 | 原 Evidence 列表、原文定位和预览 |
| Task Center | 研究任务 / 首页快捷工作台 | 原刷新、取消、重试和恢复 |
| Trace | 原聊天消息组件 | 原执行观测展示 |
| Approval Card | 原聊天消息组件 | 原确认/取消操作 |

没有调整组件内部业务逻辑、API 客户端、后端工具或 Evidence 结构。

## 8. 验证

新增 17 项 Streamlit AppTest 测试（含参数化展开）：

- 应用启动、默认 Dashboard、Header、菜单与不可用指标。
- 八个区域导航和独立页面渲染。
- 原聊天调用、Trace 结果保留、Evidence 定位及跨页状态保留。
- 文档上传入口、筛选状态跨页保留。
- Task Center 使用既有刷新接口，首页反映已载入任务。
- 知识库/报告中心/使用统计占位不发起业务请求。
- 文件数量不受文档筛选影响，读取失败不显示为零。
- 非法路由安全回退首页。

原有 `tests/test_frontend_workspace.py` 未修改，13 项继续通过。新增与原前端专项合计 30 passed，10.54 秒。

完整回归：`pytest -q` 为 **683 passed，0 failed，0 skipped，47.47 秒**（原有 666 项 + 新增 17 项）。

`git diff v6-final-stable -- backend` 为空；原 `frontend/components/`、`frontend/api_client.py` 及全部旧测试未修改，`git diff --check` 通过。AppTest 验证页面组件树与交互，不替代人工对实际浏览器外观的验收。

## 9. V7.1 规划与当前限制

V7.1 可沿用此导航和页面边界接入知识库交互，复用已有文件 API；任何涉及新的后端数据模型或接口的需求应先明确范围。

后续阶段再接入报告中心、任务体验、使用统计、历史会话及设置编辑。当前没有实现知识库管理、报告列表/导出 UI、账号系统或计费用量统计。

当前功能组件保留 V6 前端契约，包括既有上传类型与任务展示分类。本阶段不改变后端能力或补齐所有 V6 功能的 UI。由于没有新增前端依赖，运行入口仍为 `streamlit run frontend/app.py`。

完成回归后提交 `V7.0 frontend product foundation`，不创建 tag，停止并等待人工验收。
