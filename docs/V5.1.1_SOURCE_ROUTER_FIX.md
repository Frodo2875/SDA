# V5.1.1 Source Router Tool Boundary 修正记录

## 1. 修正范围

V5.1.1 只修复 Source Router 未约束 Agent Tool 集合的问题，不新增 Web Retrieval
能力，也不修改 Web Parser、Search Provider、Evidence Schema 或既有检索实现。

## 2. 问题原因

V5.1 的 `run_agent()` 已在调用 Agent Runtime 前生成 `source_route`，但该值只被
附加到最终响应：

1. `_run_agent_core()` 没有接收 `source_route`；
2. LLM 每轮始终收到全量 `TOOL_DEFINITIONS`；
3. Tool 执行器只有 Domain allow-list，没有 Source allow-list；
4. 因此 `LOCAL` 策略虽然不会自动联网，模型仍能看到并尝试调用
   `retrieve_web`。

## 3. 修改方案

新增 `backend/services/tool_scope_resolver.py`，将经过 Schema 校验的
`source_strategy` 转换为不可变的 `SourceToolScope`：

| Source Strategy | 模型可见及运行时允许的 Source Tool 范围 | Web 模式约束 |
| --- | --- | --- |
| `LOCAL` | 既有 Tool，但移除 `retrieve_web` | 禁止 Web |
| `WEB` | 仅 `retrieve_web` | 只允许 `query` Search 模式 |
| `DIRECT_URL` | 仅 `retrieve_web` | 只允许 `url` Fetch 模式 |
| `BOTH` | 既有 Local 与 Web Tool | Search 或 Direct URL 均可 |

Agent Runtime 现在执行两层防护：

1. **调用前最小暴露**：每次 LLM 调用只传递 Source Scope 允许的 Tool
   definitions；
2. **执行前强制校验**：即使模型伪造未暴露的 Tool Call，执行器仍返回
   `TOOL_NOT_ALLOWED_FOR_SOURCE`，不会进入 Tool handler。

Source Scope 与既有 Domain Scope 相互独立：Source Scope 管理 Local/Web
来源边界，Domain Scope 继续使用 V4 原有运行时校验，避免改变 V4 Domain Router
语义。最终 Tool 执行必须同时通过两者。

修正后的调用链为：

```text
User Request
    -> Source Router
    -> source_strategy
    -> Tool Scope Resolver
    -> filtered Tool definitions
    -> Agent Runtime
    -> execution-time Source + Domain checks
    -> allowed Tool
```

LLM Trace 的 `available_tool_count` 记录实际暴露数量，并在 metrics 中记录
`source_strategy`；不记录模型内部推理。

## 4. 修改文件

- `backend/services/tool_scope_resolver.py`
  - 新增 Source Tool Scope 解析和执行参数模式校验。
- `backend/agent.py`
  - 将 `source_route` 在首次 LLM/Tool 调用前传入 Runtime；
  - 过滤模型可见 Tool definitions；
  - 在 Tool handler 前强制执行 Source Scope 校验；
  - Trace 使用实际 Tool 数量并记录策略。
- `tests/test_web_retrieval_v5.py`
  - 新增 LOCAL、WEB、DIRECT_URL、BOTH 四类 Agent Runtime 边界测试。
- `tests/test_agent.py`
  - 更新既有本地场景断言，确认 `retrieve_web` 不再暴露。
- `docs/V5.1.1_SOURCE_ROUTER_FIX.md`
  - 本修正记录。

未修改 Evidence、Web Parser、Search Provider、数据库、前端或依赖。

## 5. 测试覆盖

新增测试验证：

1. `LOCAL` 不向模型暴露 `retrieve_web`，伪造调用也在 handler 前被拒绝；
2. `WEB` 仅暴露并允许 Web Search；
3. `DIRECT_URL` 仅暴露 Web Tool，拒绝 Search 参数，只允许 URL Fetch；
4. `BOTH` 同时暴露并允许 Local 与 Web Tool；
5. Search Provider 和 URL Fetch 继续使用 Fake Provider、Resolver 和 Transport，
   不依赖公网。

目标回归：

```text
36 passed in 1.34s
```

完整回归：

```text
429 passed in 30.05s
```

V1-V5.1 既有测试全部通过，原 425 项未减少，新增 4 项边界测试。

## 6. 明确未包含

本修正没有实现 Evidence 4.0、Authority/Freshness 评分、Cross-Source
Retrieval，也没有修改 Web 内容解析或搜索服务。本阶段完成后停止，不进入 V5.2。
