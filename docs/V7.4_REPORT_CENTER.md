# V7.4 Report Center

## 1. 设计目标

将已有 V6.4 报告的查看、下载、Evidence、审批及版本能力接入独立报告中心。前端只展示已保存字段、调用既有 API，不生成报告文件、不重新检索、不计算质量，不修改 Report Generator、Evidence Quality Gate、Version、Approval 或 Rollback。

## 2. 页面结构与范围

`frontend/pages/reports.py` 接入已有 Sidebar 报告中心菜单。

- 列表：报告名称、关联研究任务、创建时间、后端状态以及查看/下载/版本入口。
- 创建：选择已完成研究任务和标题，显式点击调用原创建报告 API；页面重跑不自动生成报告。
- 详情：基础信息、任务说明、摘要、核心结论、章节、Warning、Evidence。
- 导出：Markdown 和 Word 分别展示审批入口、下载、版本记录。
- 版本恢复：Word 可用版本提供恢复按钮，展示原 Diff/审批卡，确认或取消后显示结果。

后端没有全局报告列表接口。页面复用 V7.3 任务发现逻辑，从已知会话的研究任务 `result.reports` 及浏览器聊天中已保存报告获取引用，再逐一读取 Report API 获取当前状态。每个已知会话列表最多最近 100 个任务；不是全局或跨设备完整报告历史。提供 Task ID + Report ID 入口，便于打开当前列表未发现的已有报告。列表/详情用 Streamlit 状态切换，不新增 HTTP 页面路由。

## 3. Report API 调用清单

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/sessions/{session_id}/tasks` | 发现已知会话任务 |
| GET | `/api/research-task/{task_id}` | 读取已保存报告引用及任务所属会话 |
| POST | `/api/research-task/{task_id}/reports` | 显式创建报告，复用原生成器 |
| GET | `/api/research-task/{task_id}/reports/{report_id}` | 报告内容、状态、导出文件关联 |
| POST | `/api/research-task/{task_id}/reports/{report_id}/preview` | 申请 md/docx 导出并返回原审批动作 |
| GET | `/api/research-task/{task_id}/reports/{report_id}/download?format=md或docx` | 下载批准导出的文件字节 |
| GET | `/api/files/{file_id}/versions` | 按导出文件显示已有版本 |
| POST | `/api/files/{file_id}/rollback/{version_id}` | 原 Word 恢复预览/待审批动作 |
| POST | `/api/actions/{action_id}/confirm` 或 cancel | 原审批流程 |
| GET | `/api/evidence/{id}/locate` | 按任务所属 session_id 打开原文 |

没有新增后端 API。下载客户端单独处理二进制响应，拒绝错误状态或不匹配的内容类型，不把 JSON 错误下载为报告文件。

## 4. 预览设计

详情直接用 Streamlit Markdown 展示 Report API 保存的 summary、conclusions 和 sections，保留字段内容中的标题、列表、引用和章节结构。展示引用和后端 Warning，不改写结论或重新生成完整报告 Markdown。

结构化内容预览与导出文件明确区分：获批的 Markdown 文件在用户加载下载时，可直接渲染下载 API 返回的原文；下载的文件以当前批准导出版本为准。Word 回滚不会改写报告结构化 JSON 摘要，页面不声称摘要等于回滚后的 Word 文件。

Evidence 复用现有组件，显示文件名、定位、Web URL 等，并使用原任务 session_id 定位原文。前端不访问 backend Python 模块、数据库或文件系统。

## 5. 下载与 Approval

每种格式独立检查 Report API 返回的 export.status，只有 executed 显示加载下载入口。加载后提供 Streamlit 下载按钮，原始字节直接返回浏览器，不调用本地文档生成器或保存新文件。

未导出或待审批时提示暂不可下载，用户可点击预览申请导出。审批卡复用 `render_confirmation`，确认/取消调用既有 Action API；业务失败保持 pending 并显示错误，不伪造成功。刷新或加载下载不自动批准、不修改后端文件。

## 6. 版本管理展示

Markdown 和 Word 的版本分别通过其导出 file_id 获取，展示 version_number、created_at、status，缺失信息不推测。版本号不等于当前激活版本，页面不自行标记“当前版本”。

现有 Rollback 实现走 `_writable_word`，仅支持 Word。Word available 版本可申请恢复，传递任务所属 session_id；必须经原审批确认才执行。Markdown 保留版本展示并说明没有可用的恢复接口，不创建替代恢复逻辑。

报告详情、下载、版本列表、预览和审批异常分别显示，不通过失败状态触发重新生成报告。
