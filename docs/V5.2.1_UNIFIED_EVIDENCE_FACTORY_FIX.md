# V5.2.1 Unified Evidence Factory 修正记录

## 1. 问题

V5.2 已定义 `UnifiedEvidence`，Web Search 和 Direct URL 也已直接生成 Evidence
4.0，但本地链路仍以 Evidence 3.0 为内部主表示，直到 Agent 最终响应时才调用
`upgrade_local_evidence()`：

```text
Local Source -> Evidence 3.0 -> Agent Upgrade -> Evidence 4.0
Web/URL     -> Evidence 4.0
```

这使 Local 与 Web 的汇流点过晚，`evidence` 与 `unified_evidence` 容易被理解为两套
并行内部体系。

## 2. 原因

Evidence 3.0 的 `build_evidence()` 同时承担了四项职责：

1. 校验本地来源字段；
2. 构造 Evidence 3.0；
3. 保存 Evidence Location；
4. 生成 V1-V4 精确兼容字典。

V5.2 为避免破坏旧测试，只在 Agent 出口增加了本地升级器，没有把“Canonical 构造”
与“旧格式序列化”拆开。

## 3. 架构调整

V5.2.1 新增唯一 Canonical 创建边界 `UnifiedEvidenceFactory`：

```text
Document/PDF Retrieval ----\
Excel/CSV Table Query ------\
Image/OCR KIE ---------------> UnifiedEvidenceFactory
Visual Table ---------------/          |
Web Search ----------------/            v
Direct URL ---------------/    Canonical Evidence 4.0
                                      |
                       +--------------+--------------+
                       |                             |
               Agent/API Unified Chain      Evidence 3.0 Serializer
                                                     |
                                             V1-V4 compatibility
```

Factory 提供：

- `local()`：直接构造 `source_type=LOCAL` 的 `UnifiedEvidence`；
- `web()`：直接构造 `source_type=WEB|URL` 的 `UnifiedEvidence`。

Factory 统一执行：

- 真实内容存在性校验；
- Local 文件与 Locator 校验；
- Web URL/domain/retrieved_at 校验；
- Evidence 4.0 Schema 校验；
- Local/Web 不可信数据权限固定；
- Authority/Freshness 的既有确定性规则。

## 4. Local 生成链路迁移

下列内置生成点不再调用 Evidence 3.0 Builder：

- `backend/services/document_index.py`
  - PDF、Word、PPT、TXT、JSON、图片/OCR 的 Document Retrieval；
- `backend/tools/table_tools.py`
  - Excel 与 CSV 的结构化字段 Evidence；
- `backend/services/visual_understanding.py`
  - 图片/视觉 PDF 的 OCR/KIE 字段 Evidence；
- `backend/services/visual_table.py`
  - 视觉表格 Cell 计算 Evidence；
- `backend/services/web_retrieval.py`
  - Web Search 与 Direct URL Evidence。

这些模块现在先持有 `UnifiedEvidence` 对象，再根据外部兼容需要生成旧字典。

## 5. Evidence 3.0 兼容方案

新增：

- `serialize_evidence3_compat()`
- `serialize_evidence3_chain()`

兼容序列化器只接受 Canonical `LOCAL` Evidence，并负责：

1. 恢复 `structured/unstructured`；
2. 保留旧字段和旧返回形状；
3. 保存原有 Evidence Location 记录；
4. 维持 V1-V4 精确字段契约。

旧 `build_evidence()` 仍保留给旧调用方，但实现已反转为：

```text
build_evidence()
    -> UnifiedEvidenceFactory.local()
    -> serialize_evidence3_compat()
```

因此即使旧调用入口也不会先构造 Evidence 3.0。

## 6. Agent 与 API 兼容

Agent 不再从 `evidence` 调用 `upgrade_local_evidence()`。新增的 Canonical Collector
只读取内置 Tool 的 `unified_evidence` Factory Sidecar，并按 conclusion Tool 实际使用的
Evidence ID 过滤。

外部字段保持：

- `unified_evidence`：Canonical Evidence 4.0，供新 API、Answer 和前端使用；
- `evidence`：旧 API 兼容视图。本地来源保持 Evidence 3.0，Web/URL 因旧版本没有对应
  类型而保持 Evidence 4.0。

双字段只存在于外部兼容边界；内部生成、合并和新展示链均以 Evidence 4.0 为主对象。

## 8. 测试

新增 5 个测试实例：

1. PDF Retrieval 直接输出 Canonical LOCAL Evidence；
2. Excel Query 直接输出 Canonical LOCAL Evidence；
3. CSV Query 直接输出 Canonical LOCAL Evidence；
4. Image/OCR KIE 直接输出 Canonical LOCAL Evidence；
5. Web 与 Mixed Chain 均使用 Factory Canonical Evidence。

每项 Local 测试同时验证：

- Canonical 对象先存在；
- Compatibility Evidence 后生成；
- 两者 `evidence_id` 一致；
- 旧 `structured/unstructured` 和定位字段未丢失。

完整回归：

```text
441 passed in 31.57s
```

V5.2 的 436 项全部保留，新增 5 项 Factory 集成测试。

## 9. 范围确认

本修正没有实现 Cross-Source Retrieval、Query Rewrite、Retrieval Planning、
Multi-round Search、Evidence Sufficiency 或任何 V5.3 功能；Authority 仍只来自显式
metadata/provider 属性或固定 `unknown`，没有使用 LLM 判断。
